# Contextual panels contract v1 (private candidate)

Copy these scripts into `res://scripts/electronics/contextual_panels/` only after core integration review. They are currently private source under `review_artifacts/circuit_redesign_20261107/contextual_panels/` and are not imported by the live game.

- `component_picker.gd`: `configure(profile, catalog, kit_limits, creative)` then `open_picker()`; `chosen(type_id, instance_id)` and `closed` signals. Core sets `canvas.first=""; canvas.selected_type=type_id` and records the chosen instance through its existing `Selection.bind_new_parts` workflow. Picker uses canonical `inventory_value_search/query.gd` for numeric values; no duplicate unit parser. It does not place or save components.
- `selection_inspector.gd`: `bind_selection(part, definition, edit_validator)`; empty part hides panel. Emits `action_requested(op, payload)` for `rotate`, `remove`, `copy`, `code`, or `property`. Core maps these to actual canvas/model operations, runs Board.validate and saves through existing authority. The validator callable receives `(part, field, raw_text)` and returns `{ok,value,error}`; no local unverified model mutation.
- `analyzer_panel.gd`: `bind_canvas(canvas, allowed)`; `open_panel()`, `close_panel()`. Basic/Advanced toggles directly set existing canvas analyzer/overlay/probe/capture properties and calls its existing methods. Advanced preserves timing, hold, clear and threshold. No simulated readings are fabricated; readout is exactly `canvas.inspection_text()`.
- `bench_connections.gd`: `configure(ports, rows, validator, apply)`; `open_panel()`. Validator receives `(port_index, raw_hole)` and returns `{ok,value,error}`. Apply callback receives `(index, normalized_hole)` and must commit via existing Board/profile authority path. No local direct save.
- `status_help.gd`: `set_status(code, detail)` with factual short statuses; click to reveal caller-supplied detail. No diagnostic inference/solver.

`panel_host.gd` attaches to core `workspace.canvas` and consumes its `panel_requested` and `selection_changed` signals. Core passes `callbacks.panel_data` (`profile`, `catalog`, `limits`, `creative`, `analyzer_allowed`) and `callbacks.panel_actions` (`record_instance`, `validate_property`, `apply_property`, `validate_port`, `apply_port`, `open_projects`). The staged `CORE_WORKSPACE_MOUNT.patch` adds exactly this mount to the current core candidate with a whole-file SHA preimage. This is the precise extra interface beyond core CONTRACT.md. Core must mount the floating panels beside its breadboard canvas, and show only the picker on Add Component. Main root/canvas/toolbars/shortcuts remain owned by core. Requested cursor preview and compatible-hole highlighting require core canvas changes and are not claimed by this packet. See `INTEGRATION.md` for exact current callbacks.
