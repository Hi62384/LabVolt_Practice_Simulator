# Academic UI adoption

Academic controls consume the shared design system API. Dashboard has responsive course cards, record cards, lecture/lab week summaries from the academic menu query, completion/attendance distinction, exam/retake badges and a primary start action. `campus_adapter.course_record` delegates to the existing query module. No grade computation is duplicated in UI.

Paper chrome has wrapping icon/label navigation, exam and returned-mark badges, themed actions, and the original reader-generation guards. Calculator keys have larger hit targets and descriptive tooltips, and invalid expressions expose an error state. Expression templates and table actions have larger focused controls. Workspace graph actions use labeled icons; read-only entry gets a status badge. MTH255 impedance chrome contains a horizontal scroller around the unchanged schematic. Challenge actions use consistent icons and primary submission controls with existing command payloads.

Source checks verified design resource paths, responsive-grid API properties, reader generation/visibility guards, queued answers/ink/annotation signals, challenge attempt IDs and request routes, read-only propagation, reference/demonstration signal forwarding, and activity-start disabled state. No engine parsing, visual acceptance or network acceptance is claimed. Main should visually check 1280x720 and 1920x1080, keyboard focus order, wrapped paper toolbar, large calculator side panel, course cards, returned/exam badges, graph toolbar and schematic scrolling after the active session. Printable paper themes, expression drawing, graph axes, impedance geometry, ink, and annotations remain specialized.

Changed UI files: campus_dashboard.gd, campus_adapter.gd, campus_map.gd, paper_ui.gd, math_ui/workspace.gd, expression_editor.gd, table_editor.gd, mth255/worksheet_adapter.gd, scientific_calculator.gd and lab_challenges/panel.gd. No shared session, network, profile, grading-policy, or menu files changed in this UI pass.
