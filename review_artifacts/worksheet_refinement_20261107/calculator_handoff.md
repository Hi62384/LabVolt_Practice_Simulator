# LV–253 drawer refinement

`scripts/ui/paper_workspace/calculator/drawer.gd` is the only changed source file. It keeps the existing `scientific_calculator.gd` instance and all of its actual buttons, expression handling, memory, angle mode, and LineEdit. The drawer adds a blue-gray physical bezel, raised key styles, LCD glass style, a slim grip and compact icon pin. Its carrier is transparent, so there is no large backing panel. Calculator, carrier, and drawer local rotations are set to zero in the update path. The host must also keep `screen` and its ancestors unrotated for exact screen alignment.

At rest the body shows a 36 px strip at the right edge. `dock_rect(true)` exposes the full body with 20 px right margin; `measured_rect()` reports the actual moving bounds. `set_occlusion_rect(rect)` takes a rectangle in drawer-local coordinates and shifts the expanded calculator left if the open pencil case would overlap it. Clear it with `Rect2()` when the case retracts. The exact-preimage integration proposal is `calculator_adapter.patch`; only the main owner should apply it after checking its context. This is needed at 1366×768 because both tall objects cannot stack fully on the right while expanded. A temporary hover bridge lets the pointer travel from the right-edge peek to the shifted body, then stops tracking the intervening paper once the pointer reaches the calculator.

Hover uses a 0.16 s close delay. Pin locks the calculator open and enables drag from the slim top grip; releasing and unpinning animates back to the right dock before normal hover can reopen it. The full-screen root ignores GUI pointer hits; only the actual calculator body receives them. `snapshot_state()` / `restore_state()` remain available for the existing page rebuild integration. All entry keys and callbacks remain the original calculator's.

`calculator_source_check.py` checks the own-source hooks and models the dock/clamp formulas for 1920×1080 and 1366×768. It cannot validate Godot layout minimums, visual appearance, or live input. Runtime owner must verify those and capture screenshots when the active-game gate clears.
