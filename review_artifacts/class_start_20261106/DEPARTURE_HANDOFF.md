The school patch makes an unfinished current class assignment a 0% official record when the host observes that authenticated participant leave. It uses the existing `GradePolicy.attempt_id`, immutable archive and course metadata, checks `class_students[token].done` and the archive before writing, and does not touch prior completed marks. It removes saved-sheet restoration and disables class checkpoint/recovery. The front menu patch removes the now unreachable resume page; its home button had already been removed by the main owner before this baseline.

The private candidate now stores a versioned pending marker in the existing `teacher_records.json` archive before `_give` grants an official assessment. Pending markers have no score and are filtered from grade delivery. `PendingAssessment.settle` replaces that same assessment ID atomically with its final official result, and refuses to overwrite an already final result. The atomic writer checks open, flush and rename failures; paper delivery is blocked on marker save failure, and submission remains unmarked on result save failure. On build, abandoned markers belonging to the local authenticated host profile become one 0% result without restoring class state. `pending_assessment_candidate.gd` and `test_pending_candidate.gd` are private packet files; stage them with the candidate patch for guarded tests.

The pure packet test injects a dictionary-backed writer and checks failed prepare, failed settle, restart, duplicate settlement and preserved completed grades. No engine has run it yet.

Admission revision: initial `start_activity` now atomically persists markers for all authenticated enrolled profiles with the newly selected assessment ID before mutating the class or entering countdown. Failure returns the existing `{ok:false,error:...}` result and leaves the class unstarted. `_identify` persists a marker before admitting a new arrival into an active travel/lesson phase; failure sends the existing notice and returns without binding the identity or enrolling the student. The sheet-delivery write remains a second idempotent gate. `enroll()` stages all initial learners in one copy and publishes it only after the writer succeeds, preventing partial initial enrollment. Pre-issue restart and failed-admission regressions are in `test_pending_candidate.gd`.

The policy boundary remains unresolved for other participants when their host disappears. Their pending records are retained rather than automatically failed during startup reconciliation. The candidate sets `host_departure_in_progress` before the host's own voluntary exit and suppresses other-peer failure during that roster teardown. Ordinary remote peer removal while the host remains active still fails only that peer. What ultimately happens to the other participants' pending markers when the host quits or crashes needs the user's answer. Existing `user://campus_academic_recovery.dat` is ignored by the disabled recovery API and UI, not migrated into a resumable session.

Exact policy hook for main/root: `prepare_host_exit()` handles the host's own voluntary departure; `roster_changed()` invokes `_fail_departing` for each removed authenticated peer. Main must gate that latter call during authority shutdown/transport loss according to root's decision. Startup reconciliation deliberately settles only `local_identity`, leaving other-profile markers pending for that decision. No class restoration API is involved.

Runtime acceptance remains pending: explicit client leave before and after submission, duplicate disconnect, reconnect identity, host exit with other students, crash/restart obligation settlement, freeplay exit, and preservation of earlier course marks.
