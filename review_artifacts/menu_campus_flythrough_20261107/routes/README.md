# Campus flythrough route handoff

Install `routes.gd` at `res://scripts/campus/presentation/menu_flythrough/routes.gd` after integration review. It implements the architecture owner's `catalog()` contract. `build_routes.py` regenerates both the GDScript and human-readable `routes.json` from actual campus registry coordinates.

The catalog has 28 routes and 137 authored path points. It covers the central entrance and planted courtyard, lobby, both main floors' corridors, door-framed views of M101/M103 laboratories, M102 store, M105 gym, M104 cafeteria, M106 Tim Hortons, M108 Subway, M201/M202 lectures, M203 computer classroom, M204 library, M205 study, M208 custom circuit studio, and the dorm hall. Seven routes cross actual door openings into M201, M202, M203, M204, M205, M104, and M208. Their reaches are deliberately limited to the clear entry aisles documented in `build_routes.py`. There is no route inside M101 or near its equipment. M208 is the custom circuit workshop; dorm workshops and personal notes are separate existing interactions, not relocated or represented as store functions.

`python review_artifacts/menu_campus_flythrough_20261107/routes/build_routes.py` audits IDs, target counts, and the authored Bezier curves at 20 samples per span against conservative circulation envelopes. Interior routes are additionally checked against enlarged source-derived furniture footprints with 0.25 m camera radius. The generated curves use world-space positions and gentle handles. This is an offline swept centre and coarse obstacle audit; it does not prove Godot collision clearance from every dynamic object or verify camera framing, streaming activation, 1920×1080 rendering, menu performance, or multiplayer behavior. The runtime owner must run guarded Godot validation and inspect screenshots when resource limits permit.

The dorm hall route assumes the existing eight-room dorm shell and should be withheld if that shell is not present in menu presentation mode. The `rooms` pins specify rooms visible through portals; routes with `location=circulation` need those pins honored by the presenter. For long hall routes, preloading the listed content should be bounded and staged, or those routes should be temporarily withheld if visual content cannot be loaded within budget.
