# Classroom event director preparation

This directory contains an isolated Python reference model and contract tests. It is not loaded by Godot, does not schedule classroom activities, and does not satisfy the requested in-game feature by itself.

`classroom_director_fixture.gd` is a separate test-only translation of the lifecycle boundary. `test_classroom_director_fixture.gd` exercises it without loading the campus. It is not a production director or evidence that an event is playable.

The live class controller is `scripts/campus/academics/class_start/room_classes.gd`. `_start` creates the host-owned class and authoritative deadline; `_sign` creates individual assignments; `_advance` changes arrival to lesson and calls `_begin_assignment`; `_begin_assignment` persists enrollments before starting the official assignment. `_publish` sends per-player views. An integrated director must leave that deadline and the official assignment, answer keys, gradebook and replay rules under those existing owners.

The prototype exercises host-only selection, course and time eligibility, one active resource reservation, a bounded participant list and recent history, explicit transitions, cancellation on assessment start, disconnect handling and snapshots that cannot mutate host state. It deliberately contains no questions, scoring, inventory actions, grades, network transport or fake completion buttons. Its fixed reserve and small event limit are provisional design parameters, not claims about the eventual in-game schedule.

The separate practice-round reference model accepts only an injected answer validator; the sample test is not game content. It models host-only single submissions, deadline checks, disconnect/reconnect, late observers, and individual results revealed after closure. Integration must generate and validate questions through `CourseBridge.generate`, `public_copy` and `grade` for the same course and week. It must not expose answer keys through snapshots or apply practice results to the official archive.

`scripts/campus/academics/classroom_events/practice_round.gd` is an inactive reusable component exercising CourseBridge methods for DGS266, ETY155, ELM253, MTH147 and MTH255. It keeps the generated assignment private, publishes a provider-sanitized question, recursively rejects known private fields, checks a bounded submission on the host, and withholds feedback until closed. Its test checks a correct DGS266 response, one correct structured MTH255 response, incorrect responses across those five courses, rejoin, stale events, deadlines and nested private-field rejection. It is not connected to class sessions. Before use, audit additional nested key names and semantic answer leakage, support every course's structured response forms, bind participant identities to authenticated peers, and exercise grading across all supported course weeks and question types.

`scripts/campus/academics/classroom_events/hand_queue.gd` models a bounded host-owned raised-hand queue, single selected student, idempotent hand raising, stale event rejection and disconnect/rejoin cleanup. `participant_authority.gd` resolves a server-derived peer through the live session roster, host-owned identity map and active classroom enrollment; its `inside` argument must be computed on the host. Neither component is connected to live classes. The isolated tests do not exercise real peer authentication, UI, character animation, teacher perception or multiplayer replication. The live classroom must implement these through existing authority and animation systems rather than trusting client-supplied identities.

`classroom_action_fixture.gd` composes those existing components with a synthetic host-owned roster and tests stale class and event IDs, outside-room, non-host and mismatched-peer actions, plus cancellation on assignment transition. The gated production `practice_panel.gd` uses the existing mathematics workspace for MTH147 and MTH255; choice and scalar cases use basic controls. Its isolated tests cover structured response emission, submission status, raised-hand controls and private feedback, but not every mathematics form or visual layout.

The production `classroom_events` service, controller, view and panel are wired behind `CLASSROOM_EVENTS_ENABLED = false` in `room_classes.gd`. Their isolated host test covers eligible students, stale class/event IDs, observer snapshots, per-student result isolation, roster disconnect/rejoin with a new peer, malformed payloads, request throttling, deadline closure and assignment cancellation. It also checks handoff when the called student leaves, stable enrollment in the presence of a duplicate profile and refusal to rebind an ambiguous profile. A lightweight two-peer ENet test exercises actual RPC submission, new-peer reconnect, per-recipient feedback and assignment cancellation without loading the campus. Rebinding relies on the existing server-owned identity map; that map accepts client-supplied profile tokens and is not cryptographic authentication.

The gated feature is not playable. Before activation, complete the semantic question-payload privacy audit, event selection and timing, collision-safe integration with assessment enrollment retries, actual full-scene transport and reconnect tests, UI styling/focus and cleanup, and multiplayer/late-join and visual checks. Run the required full startup smoke after changing live code.

The gated controller schedules up to three short practice activities, uses teacher talkativeness to space them, retains feedback for ten seconds, and clears them on assignment transition. After repeated unsuccessful attempts it retries on a cooldown, so a late arrival can participate if time remains. The isolated owner test checks default-off behavior, late arrival, activity replacement, panel creation and assignment cancellation. A dismissed panel retains its contents and can be reopened with F7 until the event ends; the view test covers reopening and event replacement. The panel includes a bounded countdown, private feedback and raised-hand controls; teacher selection is represented in the per-player view, but the requested visible raised-hand animation and teacher reaction are not wired. Before activation, use host-selected lesson timing and personality-weighted event selection, review input/focus handling visually, and test assignment persistence retries and actual live-game RPC delivery.

The local full-scene two-peer test `test_classroom_live_network.gd` manually injects the controller while the normal gate remains off. One run reached host and client practice submission and the official-assignment transition, but produced shutdown RPC errors because the test removed the scene before disconnecting. After cleanup was changed, the host passed but the client timed out waiting for a transient submission-status label during the fast assessment transition. The test now records the authoritative response signal instead of relying on a panel that can disappear during transition. It still requires a clean two-peer rerun. Do not treat the earlier runs as a clean acceptance pass or enable the feature based on them.

The isolated full-scene `test_classroom_live_host.gd` passed attendance, a host practice submission, and transition to the official assignment without marking the student complete. It uses the real class lifecycle with the controller explicitly enabled only for the test; it does not replace the two-peer, reconnect, visual, or input-focus checks.

Practice snapshots now resolve the peer against the active enrollment before including submitted state, raised-hand state or private feedback. Other present peers may observe the public question but cannot obtain a student's state merely by presenting the same profile token. The focused integration and lightweight two-peer reconnect checks pass. Profile tokens themselves are not authenticated and this does not establish account security.

Practice now selects a seeded eligible question from the generated assignment and grades the corresponding private question index. Recent question indices are avoided when alternatives exist; activity spacing also takes participant count into account. Enrolled late arrivals can join an active round when more than eight seconds remain, while other visitors observe. A sampled audit checked 200 selections across all lecture weeks and four seeds, including matching private grading; it is not a complete semantic privacy or visual-input audit. Mathematics remains restricted to the first question: an additional form did not match its workspace in testing and must be resolved before expanding that selection.

The lightweight payload key audit generated every available lecture week for DGS266, ETY155, ELM253, MTH147 and MTH255 at difficulties 0 and 4 with seeds 42 and 137: 1,424 public questions, with zero matches for the adapter's known private field names. A grading audit checked all 280 questions generated across those weeks at difficulty 0 and seed 42, covering 28 course/form combinations with no failures. A separate panel audit mounted one sampled question from each of 19 mathematics lecture weeks and found no response-shape failures; this is not a visual or complete form audit. None of these audits covers all seeds, difficulties or question types; the key audit is not a semantic proof that text or diagrams never reveal answers.

The gated event service now uses `event_lifecycle.gd` to reserve a worksheet or projector in each room. It releases that reservation on failed preparation, class cancellation, question completion or timeout, and removes lifecycle records after the round leaves the room. When every participant leaves, the lifecycle enters interrupted and returns to active if someone rejoins before the deadline; the countdown continues. The focused lifecycle and integration checks pass. Quiz results include host-timed correctness and speed points after closure, with no answer or individual point value sent to observers during the question. Real equipment ownership remains open.

The gated quiz now retains a host-owned series across up to three question IDs, choosing the count from the lecture time available. One accepted submission per identity and question is graded; reconnecting on a different peer cannot earn a second award. After each question, the service awards correctness, speed and consecutive-correct bonuses once, then exposes individual totals, anonymous top-three scores and team totals when there are at least two students. An eight-second result interval precedes the next question. A late enrolled student can join an active question when more than eight seconds remain; their later score joins the same series. Assessment takeover cancels the series and frees the projector, without touching official marks. The focused multi-round test covers repeat submissions, reconnect, late join, no-answer timeout, short-lecture adaptation, and assessment cancellation. It does not validate the live projector presentation or actual two-peer full-scene transport.

Before integration, replace the prototype with a Godot implementation driven by actual course/week content, all four teacher values and applicable traits. Resolve content validation, timeouts and interrupted/resumed lesson stages, resource release, authoritative participant submissions and scoring, late joins, disconnects and reconnects, and host migration/session teardown. Make the assessment transition atomic with event cancellation even if enrollment persistence must retry. Optional practice outcomes must not alter official marks. Provide functioning interaction and compact UI rather than notifications alone.

Deferred validation: focused Godot tests; real lesson-to-assignment and replay tests; multiplayer simultaneous actions, late join and disconnect tests; classroom resource and whiteboard tests; visual and accessibility checks; and the required isolated Singleplayer and Host Game startup smoke. Run these only with sufficient resource headroom.

## Ordered remaining work

The gated service now has host checked fastest answer, teacher challenge, clue based mystery, volunteer duel, and three step pass problem rounds in addition to quiz, shared board, group, prediction, and mistake rounds. Prediction, mistake, mystery, and pass calculations use the circuit solver. A duel locks up to two volunteers, supports a solo volunteer, limits submissions to selected students, preserves the locked roster through disconnect/rejoin, and reveals an anonymous winner only after closure. A pass problem rotates between enrolled students, permits one student to complete all steps, and moves the turn past disconnected students; its public reveal omits identity tokens. The fastest correct race answer wins; winner points are practice-only. Teacher challenge time depends on competency, focus, and class size; its authoritative answer is graded normally. The host publishes a bounded teacher result comment based on the round and teacher traits, and the lecture faculty model shows it as a replicated overhead reaction. This is a caption, not TTS. Focused tests passed for these paths and the required isolated menu routes passed. The gate remains off pending full scene multiplayer and visual checks below. The current demonstration is an abstract solved circuit, not a physical lab bench interaction. The classroom mystery currently uses a verified incorrect current solution with timed clues, not an interactable broken circuit.

The lightweight ENet fixture requires one host and one client process. Run `python tests/campus/academics/run_classroom_events_network.py` to launch both with isolated user data. It defers itself when less than 2,300 MiB physical memory is free; that threshold was not met in the latest session. The direct Godot script now prints usage and exits if no peer role is supplied. The runner and new game modes still need a clean two-peer run when memory is available.

The gated ELM253 lab path now has a live AC station observation round. The host selects an enrolled student's assigned bench, reserves that station for the round, records a powered voltmeter reading, and watches the authoritative station revision and solver readings while students use the existing equipment controls. Students predict whether the reading will rise, fall, or remain about the same. The measured value or station fault is revealed only after the round closes. Power loss, a missing reading, and a tripped station invalidate any earlier measurement; an unchanged station produces no fabricated result. The reservation is released on completion or class cancellation. This does not operate equipment on behalf of a teacher, add official marks, or provide a spoken reaction. `test_classroom_physical.gd` covers these boundaries in a synthetic host fixture but has not yet run: physical memory remained below the admission threshold after this change. The required menu startup smoke also remains pending for this change. Keep the gate disabled until both pass and a full scene multiplayer/visual check confirms the lab interaction.

The existing faculty perception path now notifies the gated controller when the host notices a classroom text or voice disruption during a lesson. The controller limits this to one interruption per class every twenty seconds, delays the next optional activity for twelve seconds, and asks the active round to show a six-second anonymous notice. It does not stop an active answer window, identify the student to other peers, or change attendance or grades. Cooldown state is cleared when the class ends or the controller disables. The synthetic physical round fixture checks the notice's teacher, cooldown, and expiry boundaries; the full scene reaction and peer delivery remain unverified. Teacher relationship loading also tries its validated backup when the primary save is damaged and avoids copying a corrupt primary over that backup. Its focused regression is prepared but unrun under the same memory guard.

The host can now call one or two enrolled, present students during a practice or quiz round even when nobody raises a hand. High difficulty and focus favor a nonvolunteer first; otherwise a volunteer has priority, and focused teachers may call a nonvolunteer if no hand is raised. The event ID varies the selected student between rounds, while per-round state prevents repeated calls to the same person. Pass, physical, and volunteer duel modes keep their own turn rules. A called student is visible only as a selected state to that student and a generic called state to observers. Focused hand-queue and owner fixtures were extended but are unrun. This is not yet a 3D hand animation or a full teacher speech/gesture sequence. The physical reader now processes each station revision once, so a power cycle cannot revalidate an old reading without a new revision.

The controller now uses `event_selector.gd` to rank bounded eligible activities using the current teaching stage and objectives, four numerical teacher values, description traits, player count, recent modes, and board availability. A class ID and activity number seed the choice, so the host can reproduce it; the service remains the final authority on content, room, time and resource eligibility. The controller tries at most three ranked modes plus a lecture practice fallback. The first activity does not start a multi-round quiz before students have seen another activity. Controller-started rounds now have a three-second announcement stage with no answer controls or private question data; direct service fixtures stay immediate unless they request staging. The host rejects early submissions, publishes the active prompt when the stage opens, and cancels both stages on assessment takeover. The selector and owner fixtures are prepared but unrun. Actor gestures and full-scene UI/network acceptance remain outstanding.

When a student is called, the host now asks the existing faculty presentation system to turn the teacher toward that enrolled student's current room position. Enrollment is synchronized before timed calls to avoid selecting a departed peer. This gaze hook has not been visually verified and does not add a hand-raise animation.

The host now offers one private teacher hint and, after an incorrect first answer with at least five seconds remaining, one private retry in ordinary practice, board, group and beat-the-teacher rounds. Hints derive only from the already public question format. Partial feedback reduces the provider's score to a coarse message and never sends its rubric, expected value or answer; it is retained for the same enrolled identity across a disconnect and cleared with the round. Quizzes, pass-the-problem, demonstrations and physical rounds keep their original submission rules. The panel has a bounded hint control and shows the retry message only to its recipient. Focused round, service and panel fixtures cover unsupported hint modes, malformed requests, observer isolation, reconnect, a final second attempt, a late first answer and assessment cancellation. These fixtures and the required startup smoke remain unrun under the memory guard.

Source review found that shared board contributions previously omitted an event-ID check after a new round replaced the old one. The service now checks the active event ID before dispatching every action. The shared-work fixture covers a stale contribution after replacement, plus balanced assignment and note isolation for eight synthetic students. These additions are unrun. Quiz scoring is guarded by the round's `closed` transition and series completion count; no second award path was found in this source review. The host retains provider feedback, while open-round snapshots expose only the public question and the current student's coarse retry message. Closed rounds intentionally reveal the answer for supported modes.
