# Shared lost-and-found claim authority

This Worker is deployed at `https://labvolt-claim-authority.arshya-ghafaryan.workers.dev`, independently of the personal room relays. Every host must use that same HTTPS URL as `network/labvolt/claim_authority_url` in `project.godot`, or set `LABVOLT_CLAIM_AUTHORITY_URL` on every host. Do not point it at a personal relay: each personal relay has separate storage.

The deployment target account is recorded in `wrangler.jsonc`. On an authorized machine, sign in with Wrangler and run `node relay/node_modules/wrangler/wrangler-dist/cli.js deploy --config claim_authority/wrangler.jsonc` for updates. This Worker is a shared game service; do not redeploy it separately under each player's account.

The claim token is a random 128-bit secret created when an item is discarded. The host sends its SHA-256 digest in the URL and the token in an Authorization header. One of 256 Durable Object shards records the first successful claim in a storage transaction. Later claims of that token return HTTP 409. Each shard has a 1,000-claim cap, so untrusted requests cannot create unlimited Durable Objects or storage entries. The game refuses online pickups when the shared service is unavailable, rather than silently using host-local state.

This enforces **at most one completed claim per token across cooperative hosts**. Pickups first reserve a token for two minutes. A failed transfer releases the reservation; if the host crashes before delivery, the reservation expires and the owner's unchanged local pool can be imported again. The host commits the shared claim after its inventory award succeeds and retries a failed commit while the session remains alive. The claim and inventory award are still separate transactions: a crash after an award but before shared commit can leave an ambiguous delivery. A hostile client that fabricates a new token and parcel is outside this guarantee; preventing that requires centrally registered, authenticated item ownership and a durable inventory transfer protocol. Do not describe this as an exactly-once or anti-cheat item system.

On import, the host checks the claim status before making a saved item visible. The client sends entries individually and retries until the host acknowledges each one. When the visible room is full, accepted entries wait in the host queue and fill spaces as they open. On owner departure, both the displayed items and queued entries are removed from that host; the owner's unclaimed local entries remain for the next server.

For a local authority test, run Wrangler with `relay/node_modules/wrangler/bin/wrangler.js dev --config claim_authority/wrangler.jsonc --ip 127.0.0.1 --port 28767` and set `LABVOLT_CLAIM_AUTHORITY_URL=http://127.0.0.1:28767` in a debug build. Release builds accept HTTPS only.
